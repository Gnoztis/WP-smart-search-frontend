# WP Smart Search (Frontend)

AJAX-поиск по сайту: страница результатов с фасетными фильтрами, подсказками
при вводе, «возможно, вы имели в виду», историей запросов и блоками «похожие
записи» / «похожие запросы». Работает на собственном полнотекстовом индексе,
без внешних сервисов.

Версия 5.5.0. Требуется WordPress 7.0+, PHP 8.0+.

## Как это работает

Плагин не добавляет шорткод или блок: он подменяет шаблон страницы поиска
(`?s=…`, `is_search()`), поэтому встроенный поиск темы начинает работать
через AJAX — с фильтрами, подсказками и пагинацией без перезагрузки страницы.
Своя форма на этой странице — обычный GET-запрос с полями `s`, `cat`, `pt`,
`tags`, `xtags`, `paged`, поэтому ссылку на результат можно скопировать и
отправить.

Для скорости плагин ведёт индекс (`wp_wssf_index`: стемы заголовка, текста,
цитаты и меток) и ищет сначала по нему (`MATCH … AGAINST`), а если индекс
недоступен или пуст — обычным `LIKE`-поиском. Индексация идёт при
сохранении записи, по WP-Cron и вручную из админки.

## Установка

1. Скопировать каталог `wp-smart-search-frontend` в `wp-content/plugins/`.
2. Активировать плагин в разделе «Плагины» — при активации создаются таблицы
   индекса и служебные индексы в стандартных таблицах WordPress.
3. Открыть «Настройки → WP Smart Search» и на вкладке «Обслуживание» нажать
   «Переиндексировать всё».

Плагин самодостаточен: всё, что ему нужно, лежит в его же каталоге. Нет
Composer, нет каталога `vendor/`, нет сборки — каталог из репозитория и есть
релиз, копировать нужно его целиком. Автозагрузка классов реализована
собственным загрузчиком плагина (`includes/autoload.php` и
`includes/class-autoloader.php`), внешних зависимостей у плагина нет.

## Возможности

| Что | Как |
|---|---|
| AJAX-поиск | результаты обновляются без перезагрузки, состояние — в URL |
| Фильтры | категория, тип контента, метки: включить и исключить; панель фильтров на мобильных |
| Морфология | стеммеры для русского и английского, списки стоп-слов редактируются |
| Автодополнение | подсказки по префиксу из таблицы терминов, с fuzzy-fallback |
| «Возможно, вы имели в виду…» | исправление опечаток и неверной раскладки, если точный запрос ничего не нашёл |
| Подсказки при пустой выдаче | убрать слово, искать любое из слов, снять фильтры и т. п. |
| История поиска | у авторизованных, хранится в метаданных пользователя, отключается в настройках |
| Похожие записи | MinHash-подписи (Jaccard ≥ 0.5) |
| Похожие запросы | co-occurrence по IOC-карте: CVE, BDU, ATT&CK, IP, домены, URL, хеши, YARA-правила |
| Технические идентификаторы | IOC-значения ищутся точным совпадением подстроки, не стеммятся |
| Нагрузка | ограничение частоты запросов, необязательные security-заголовки и CSP |

## Настройки

Всё в «Настройки → WP Smart Search»:

- **Статус** — размер и заполненность индекса, кнопки переиндексации, кэш,
  статистика.
- **Настройки** — типы контента, антиспам CleanTalk, TTL вердиктов, YARA,
  автодополнение, индексация и WP-Cron, похожие записи, security-заголовки и
  CSP, подсказки и история.
- **Расширение запроса** — PRF и синонимы, опечатки.
- **Ранжирование** — синонимы, веса типов контента, баланс терминов.
- **Диагностика** — окружение, тест поиска (FULLTEXT и LIKE отдельно),
  тест CleanTalk, состояние кэша.
- **Обслуживание** — сброс и пересоздание индекса, очистка кэшей и счётчиков.

## Антиспам CleanTalk

Проверка поисковых запросов через CleanTalk — **необязательная** интеграция.

- Если плагин CleanTalk установлен, проверка включается сама (режим «Авто»).
- Если его нет, не вызывается ни одна функция CleanTalk: поиск работает как
  обычно, в форме нет служебных полей, в логах нет упоминаний `apbct_*`.
- Режим переключается в «Настройки → WP Smart Search → Антиспам CleanTalk»:
  «Авто» (по умолчанию), «Всегда включена», «Выключена». В админке видно,
  обнаружен ли CleanTalk и выполняется ли проверка сейчас.

Фильтры для сайтов с нестандартными условиями:

```php
// Считать CleanTalk установленным (например, на стенде с заглушкой).
add_filter( 'wssf_cleantalk_available', '__return_true' );

// Не проверять запросы авторизованных пользователей.
add_filter( 'wssf_cleantalk_skip_for_logged_in', '__return_true' );

// Строгий режим: очищать поля CleanTalk перед проверкой (true) или нет (false).
add_filter( 'wssf_cleantalk_strict_mode', '__return_false' );

// Сколько вызовов API CleanTalk разрешено в минуту.
add_filter( 'wssf_ct_api_rate_max', static fn(): int => 20 );
```

## Кэш Redis

Кэш результатов, подсказок и вердиктов работает только через PHP-расширение
`redis` (phpredis). Плагинов объектного кэша и транзиентов в качестве кэша нет:
если расширения нет или сервер не отвечает, кэширования просто нет, а поиск
работает напрямую. Это осознанный выбор — запись в `wp_options` дороже
запроса, который она экономит.

- Подключение ленивое, на первом обращении к кэшу.
- После сбоя плагин не трогает Redis 60 секунд (опция `wssf_redis_down_until`),
  чтобы мёртвый сервер не тормозил запросы.
- Ключи изолированы по сайту: `wssf:{hash}` от `home_url()`, имени базы и
  префикса таблиц, поэтому стенд и прод не делят кэш.
- Настройки — константы в `wp-config.php`:
  `WSSF_REDIS_HOST`, `WSSF_REDIS_PORT`, `WSSF_REDIS_PASSWORD`,
  `WSSF_REDIS_DATABASE`, `WSSF_REDIS_TIMEOUT` (по умолчанию 0.2 с).
  Понимаются и `WP_REDIS_*` / `WSS_REDIS_*`, и фильтр:

```php
add_filter( 'wssf_redis_config', static function ( array $config ): array {
	$config['host']    = '127.0.0.1';
	$config['port']    = 6379;
	$config['timeout'] = 0.2;
	return $config;
} );
```

Redis рекомендуется: без него кэш результатов не работает, поэтому подсказки на
«неизвестном» вводе (автодополнение и проверка опечаток) считаются заново на
каждый запрос, а вердикт CleanTalk не запоминается — проверка идёт при каждом
поиске (количество обращений к API при этом ограничено квотой). Состояние кэша
видно на вкладке «Диагностика».

Словарь для исправления опечаток устроен отдельно и работает без Redis: это
5000 самых частых стемов из таблицы терминов, он хранится в транзиенте с TTL
6 часов и ключом версии индекса, поэтому пересобирается только при изменении
индекса, а не на каждый запрос. Если на сайте не работают и транзиенты
(объектный кэш без персистентности), словарь целиком не строится: для каждого
слова выполняется ограниченный запрос по его первым двум буквам. Плата за это —
опечатка внутри первых двух букв на таком сайте не исправляется.

## Ограничение частоты и прокси

Публичный AJAX-поиск доступен незалогиненным, поэтому запросы ограничены:
30 в минуту на гостя и 30 в минуту на авторизованного пользователя. Повышенный
лимит — 300 в минуту — действует только для авторизованных на теме
**WPCommunity** (и её дочерних темах): сообщество рассчитано на активный поиск,
на любой другой теме повышение не применяется. Тема определяется по slug
родительской темы (`get_template()`), а не по названию, куки или заголовкам,
поэтому запрос не может «выпросить» повышенный лимит.

Изменить условие и лимиты можно фильтрами:

```php
// Повышенный лимит для другой темы (slug родительской темы).
add_filter( 'wssf_rate_limit_theme_slug', static fn(): string => 'my-community' );

// Свой лимит: $max, $is_user, $is_community_theme.
add_filter( 'wssf_rate_limit_max', static function ( int $max, bool $is_user, bool $community ): int {
	return $is_user ? 120 : 30;
}, 10, 3 );
```

IP берётся из `REMOTE_ADDR`; заголовки `X-Forwarded-For` / `X-Real-IP`
читаются только для прокси, перечисленных в фильтре (по умолчанию список пуст —
подделывать заголовок бесполезно):

```php
// IP вашего балансировщика или обратного прокси.
add_filter( 'wssf_trusted_proxies', static fn(): array => [ '10.0.0.1' ] );
```

Если сайт стоит за прокси или CDN, фильтр нужно заполнить, иначе все
посетители будут считаться одним клиентом.

## Обновления

Плагин обновляется штатным механизмом WordPress из репозитория
[Gnoztis/WP-smart-search-frontend](https://github.com/Gnoztis/WP-smart-search-frontend):
берётся более новая версия из последнего релиза GitHub и тегов вида `X.Y.Z` /
`vX.Y.Z`; при равенстве версий выигрывает релиз — у него есть описание
изменений. Архив — zip-ассет релиза или zipball GitHub. Пакет принимается
только по `https` и только с доменов GitHub.

Установленная версия определяется по шапке файла плагина на диске, поэтому
после обновления «фантомное» предложение той же версии не появляется.
Проверка кэшируется на 6 часов, ошибка — на 15 минут (столько плагин ждёт
перед повторной попыткой). Кнопка «Проверить обновления» в строке плагина
сбрасывает кэш и **игнорирует паузу после ошибки**: это явный запрос, а не
фоновая проверка. Если проверка не удалась, на странице «Плагины» появляется
уведомление с кодом ответа GitHub и подсказкой: «403 (лимит GitHub API)»,
«токен отклонён», «нет связи с GitHub». Ответ 404 считается нормальным —
например, когда в репозитории есть теги, но нет GitHub-релиза.

### Токен GitHub (необязательно)

Без токена GitHub разрешает **60 запросов в час на IP** — этого хватает, но на
общем хостинге лимит делят все сайты, и проверка обновлений может упираться в
403. С токеном лимит — **5000 запросов в час**. Токен не обязателен: без него
плагин просто проверяет реже и показывает в админке, что именно произошло.

```php
// wp-config.php
define( 'WSSF_GITHUB_TOKEN', 'github_pat_…' );
```

Подойдёт fine-grained PAT с доступом **Contents: Read** только к репозиторию
плагина — больше ничего ему не нужно. Токен передаётся только на хосты GitHub
(`api.github.com`, `codeload.github.com`, `objects.githubusercontent.com` и
`github.com` — и только для архива этого репозитория) и никогда не уходит на
другие адреса. Альтернатива константе — фильтр `wssf_github_token`.

## Удаление

При удалении плагина (не деактивации) `uninstall.php` удаляет только свои
данные: опции `wssf_*`, транзиенты и служебные строки `_wssf_*`, таблицы
`*_wssf_index`, `*_wssf_terms`, `*_wssf_embeddings`, `*_wssf_stopwords`,
`*_wssf_ioc_map`, `*_wssf_minhash`, служебные индексы в стандартных таблицах и
метаданные истории поиска. Записи, метки и настройки WordPress не трогаются.
